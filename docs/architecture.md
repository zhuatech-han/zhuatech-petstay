# PetStay 架构与数据

知华科技（上海如静知华信息科技有限公司） · https://www.zhuatech.cn/ · 微信 zhuatech / zhuatech2。

浏览器（手机H5／桌面）→ Nginx同源 `/api` → Java 21 / Spring Boot 4.0.7 → MySQL 8.4。Vue 3.5.43、Vite 8.1.5，Node 24.19.0；Flyway版本化迁移。Session保存在应用内存，照片二进制保存在数据库，重启要求重新登录，业务数据与照片持久化。

## 身份与访问

账户、角色、团队、权限、菜单、字典、设置、审计属于V1；会员、宠物、照护方、档期、需求、报价、订单、每日任务、交接记录、私有图片、线下流水、评价属于V2。公开注册固定会员角色；运营与管理员通过后台配置。会员可同时申请成为照护者。具体对象归属、参与方和运营团队范围在服务端检查，不依赖菜单隐藏。

## 一致性

写事务锁定平台主团队行并使用READ_COMMITTED；选定报价在同一事务内复核档期、容量、资料版本、宠物占用，冻结订单快照并生成任务。状态修改提交version，旧版本拒绝；报价重提创建新行，不覆盖旧价。已完成任务的修订追加历史；退款关联原收款，不覆盖流水。全局写锁适合单平台、单实例及低容量部署；门店员工关系提供店间业务隔离，不宣称独立SaaS租户或高并发能力。

## 时间与金额

业务日期依据平台运营时区（默认Asia/Shanghai）；数据库时间按UTC连接。日期区间起日含、末日不含。寄养按夜数，上门按每天固定预约窗口计算次数。界面用人民币元输入，接口以整数分存储；固定报价不因提前结束自动减少。预约窗口是计划，不是GPS到场证明。

## 迁移与初始化

`backend/src/main/resources/db/migration/`内的V1、V2及V3启动自动执行；Hibernate只validate，不自动改表。首次启动创建管理员、运营角色、会员角色、菜单、权限、字典与设置，不创建假会员、营业门店或照护订单。没有独立重复执行的业务初始化SQL。升级先备份，新增版本迁移，禁止改写已执行版本。

V3只新增订单与照片查询索引及字典版本字段，保留V1/V2原文；不覆盖旧订单快照、照片字节和线下款项。

## V4门店与通知

新增shop_policy、shop_staff、staff_roster、care_assignment、care_handover、notification_preference及care_notification；care_order新增冻结员工模式、实际入住/接回时间及现场状态。旧数据标明LEGACY，V1/V2/V3及订单原快照不改写。新门店是既有照护服务资料，员工邀请须本人接受；店长/照护员工权限与平台角色分开。

日分派检查门店成员、班次及跨店任务负荷，使用原平台写锁和订单version。通知事件和订单变更同事务保存，按收件人/事件键唯一去重。单实例调度每30秒生成平台运营日期提醒（默认上海）、超期任务，分批10封投递。发送租约先提交，SMTP连接不持有业务锁；中断租约120秒后可重试，SMTP接收与本地记账之间崩溃可能重复邮件，不能宣称严格一次投递。
